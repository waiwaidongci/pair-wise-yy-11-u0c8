# hxyfront-62010 潜水气瓶充填台

给潜水店前台/充填工用的可操作充填台。从待充填队列选中气瓶后，依据检验日期和上次余压，
为空气、高氧（EANx）、Trimix 计算目标压力与配气比例；检验过期或氧含量与气瓶标识不符时
把该瓶移出当前批次并记录原因；操作员确认后签收，签收单长期保留，同一气瓶再次到店可翻查历史。

## 功能

- **待充填队列**：默认按检验有效期最短优先排序；每张卡显示计划位置。可一键临时加急，
  加急瓶按加急时间置顶，取消加急后回到原计划位置。
- **充填批次**：勾选气瓶加入批次，可按预设（空气 / EAN32 / EAN36 / Trimix 18/45 / 21/35）
  或自定义目标压力、目标 O₂/He。系统依据残压与残气成分，用分压法（先加氦、再加纯氧、
  最后空气补压，空气按 O₂ 21% 计）算出需充入的氦、纯氧与空气分压（bar）。
- **自动拦截**（阻断签收，必须移出批次并写明原因）：
  - 检验已过期；临期（≤30 天）仅警告不阻断；
  - 目标 O₂ 超过气瓶标识允许值（空气瓶 ≤21%、高氧气瓶 ≤40%、Trimix 瓶可高氧/纯氧）；
  - 高氧/空气瓶充含氦混合气；
  - 目标压力超过气瓶工作压力、余压已达目标；
  - 残气氦/氧分压过高，无法靠补压稀释到目标（需先抽残气）。
- **签收**：录入实测压力与实测 O₂/He，勾选“确认完成”后以当班操作员名义签收。
  签收单记录气瓶编号、容积、气体类型、实际压力、混合比例、充入分压、操作员和时间。
- **单瓶历史**：按气瓶编号查询该瓶全部签收单与批次拦截记录；旧瓶再次到店入队时更新余压，
  历史记录保留。
- **持久化**：全部数据（气瓶档案、队列位置、加急状态、批次、签收单、拦截记录、操作员）
  保存在浏览器 localStorage，关闭页面再打开状态不丢。顶栏可一键重置为演示数据。

## 技术栈

React 19 + Vite + TypeScript，无后端，数据存 localStorage。

- `src/types.ts`：数据模型（气瓶、批次项、签收单、拦截记录）
- `src/fillLogic.ts`：检验日期判定、标识兼容规则、分压配气计算
- `src/store.tsx`：状态管理、localStorage 持久化、队列/加急排序、演示数据
- `src/App.tsx`：充填台界面

## 本地运行

```bash
npm install
npm run dev      # http://localhost:62010
npm run build    # 生产构建
```

开发端口：62010

> 配气结果为分压法理论估算，实际充填请以氧/氦分析仪实测值为准。
